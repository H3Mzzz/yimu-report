# 一木记账 XLSX 列语义（旧版 xlsx 数据源）

> **本文档适用于旧版 xlsx 数据源。** 当前数据源已切换为 SQLite (Custom.db)，见 [sqlite-schema.md](sqlite-schema.md)。
> xlsx 流程保留在 `~/yimu-report/backup.py` 中作为备用。

> **关键坑：`金额` 列是实付净值，不要在它上面二次扣减优惠/退款/报销。**

## 列说明

| 列名 | 语义 | 示例 |
|------|------|------|
| `金额` | **实付金额（净值）**——已扣完优惠、退款、报销后的最终支出 | 饮料原价 ¥6，优惠 ¥5，此处显示 ¥1.00 |
| `优惠` | 记录此笔交易享受的优惠额度（信息展示，不参与实付计算） | ¥5.00 |
| `退款` | 记录此笔交易享受的退款额度（信息展示，不参与实付计算） | — |
| `报销金额` | 记录可报销额度（信息展示，不参与实付计算） | — |
| `收支类型` | `收入` / `支出` | — |
| `二级分类` | 细分类别（如 `饮料`），优先于 `类别` 用于分类汇总 | — |

## 正确计算

```python
df["实际金额"] = df["原始金额"]   # 金额已是净值，保留符号
```

> **保留符号**：支出可以为负（报销退款入账），负值会让 `_extract_metrics` 里的 `.sum()` 自动冲减净支出。不要用 `abs()`——会把退款变成正支出，反而多算。`summarize()` 里 `expense_df[expense_df["实际金额"] > 0]` 已有正数过滤保护。

## 错误做法（曾被 data_processor.py 采用）

```python
实际金额 = max(0, 金额 - 退款 - 优惠 - 报销)   # 二次扣减，会把 ¥1 饮料扣成 ¥0
```

这导致了 2026-05-12 日报中饮料 ¥1.00 消失，总支出从 ¥39.80 变成 ¥38.80 的 bug。

## 摘要行格式

旧格式（误导）：`"账面原始总支出 ¥X，经优惠(¥Y)...后，净支出 ¥Z"`

新格式：`"净支出 ¥X（期间累计享受：优惠 ¥Y）"`——避免误导读者以为优惠是从原始金额里扣的。
